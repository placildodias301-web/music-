## 1. Feasibility Analysis (Section 4)

### 1.1 Technical Feasibility
- **Assessment:** **Highly Feasible (Proven by Working Prototype & Benchmark Suite)** `[VERIFIED FROM MY CODE]`.
- **Backend MIR & Signal Processing:** The core audio analysis pipeline (`backend/services/analysis_engine.py`) is fully implemented using mature, industry-standard open-source Python libraries (`librosa`, `numpy`, `scipy`, `soundfile`) and `ffmpeg` (`backend/services/audio_extract.py`) `[VERIFIED FROM MY CODE]`. Unlike deep-learning transcription models that require expensive CUDA GPUs, Wilsify AI's harmonic-percussive separation (HPSS), 36-bin/octave Constant-Q Transform (CQT), Krumhansl-Kessler key correlation, and 2-pass HMM Viterbi chord decoder run entirely on standard CPU cores at a `11,025 Hz` analysis sample rate `[VERIFIED FROM MY CODE]`.
- **Empirical Accuracy Validation:** In the repository's benchmark suite ([`docs/benchmark/README.md`](../benchmark/README.md); original `RESULTS.md` / `ground_truth.json` missing — see note at top), an untuned 16-voter key-detection ensemble evaluated across 19 ground-truth test tracks achieved **17/19 (`89.5%`) exact key accuracy** (`15/19` on leave-one-out cross-validation and `6/7` on held-out test songs), while synthetic tempo and meter validation (`docs/benchmark/synth_validation.json`) confirmed deterministic beat and chord alignment `[VERIFIED FROM MY CODE]`.
- **Frontend Real-Time Web Audio DSP:** The browser client leverages native Web Audio API primitives (`AudioContext`, `OfflineAudioContext`, `BiquadFilterNode`, `AnalyserNode`, `OscillatorNode`) for stem separation (`stemSeparation.ts`, `stemMixer.ts`), drift-free lookahead metronome scheduling (`useMetronome.ts`), and real-time YIN microphone pitch detection (`pitch.ts`) with zero server round-trip latency `[VERIFIED FROM MY CODE]`.

### 1.5 Legal and Ethical Feasibility
- **Assessment:** **Feasible with Explicit Copyright Safeguards; Requires Production Attention for Third-Party URL Fetching** `[VERIFIED FROM MY CODE]`.
1. **Mandatory User Copyright Attestation:** Before uploading or analyzing a file, the user must check a confirmation box attesting that they own the rights or have permission to analyze the recording. The frontend sends a timestamped record to `POST /api/rights-attestation`, which appends an audit entry to `wilsify-rights-attestations.jsonl` `[VERIFIED FROM MY CODE: backend/main.py, frontend/src/pages/Upload.tsx]`.
2. **Ephemeral Server Processing (Zero Copyrighted Audio Redistribution):** The backend never stores, indexes, or redistributes user-uploaded audio/video files. All temporary files (`tmp_input_path`, `wav_path`) are deleted inside `finally: cleanup(...)` blocks before or immediately after the HTTP response finishes (`backend/main.py`). Cloud sync (`0001_user_data.sql`) stores only mathematical analysis metadata (key, BPM, chord timestamps) `[VERIFIED FROM MY CODE]`.
3. **Ethical AI Lyric Generation (No Lyric Scraping):** To avoid infringing copyrighted song lyrics from commercial lyric databases, `frontend/src/lib/song/aiLyrics.ts` explicitly instructs the AI assistant to generate **original** creative lyrics inspired by the song's musical mood, key, BPM, and chord progression, while allowing users to paste their own personal lyrics or `.lrc` files locally `[VERIFIED FROM MY CODE: frontend/src/lib/song/aiLyrics.ts]`.
4. **Terms-of-Service Considerations for `yt-dlp` (`/api/fetch-media`):** While `yt-dlp` is technically effective for academic demonstrations and personal study of public videos (capped at $\le 20\text{ minutes}$ and $\le 100\text{ MB}$, non-live in `backend/services/media_fetch.py`), downloading media streams from commercial platforms like YouTube or TikTok can conflict with platform Terms of Service in a commercial production deployment `[ASSUMPTION/RECOMMENDATION]`. In a commercial rollout, `yt-dlp` should be restricted to Creative Commons / user-owned URLs or replaced with official licensed embeds `[ASSUMPTION/RECOMMENDATION]`.
5. **User Data Privacy & Row-Level Security:** User library records, practice logs, and AI chats are isolated per user via Supabase PostgreSQL Row-Level Security (`auth.uid() = user_id`), and users are provided dedicated privacy and account management views (`/settings/privacy`, `/settings/account`) `[VERIFIED FROM MY CODE]`.

## 2. SWOC Analysis (Section 6)

### 2.1 Strengths (Internal, Positive) `[VERIFIED FROM MY CODE]`
1. **End-to-End Unified Workflow:** Combines MIR audio analysis, synchronized lyric-chord sheets, stem isolation, variable-speed practice, live microphone pitch checking, a 10-instrument tuner, a 396-chord dictionary, an AI tutor, and vector PDF/MIDI export in a single web app.
2. **Hybrid Deterministic + Generative AI Architecture:** The MIR pipeline (`analysis_engine.py`) uses explainable, deterministic signal processing (HPSS, CQT chroma, HMM Viterbi) rather than hallucination-prone LLMs for audio timing, while the AI Tutor (`assistant_engine.py`) pairs Google Gemini (`gemini-flash-latest`) with a deterministic song-grounded fallback (`_grounded_answer`) and 12 music-theory rules (`RULES`).
3. **CPU-Efficient & Client-Offloaded DSP:** Server analysis runs on standard CPUs (`11,025 Hz` downsampling + startup `numba` JIT warmup), while stem separation, metronome scheduling, and YIN pitch detection run entirely in the user's browser via Web Audio API.
4. **High Verified Key Detection Accuracy:** Validated at `89.5%` (`17/19`) key accuracy on the repository's ground-truth benchmark dataset ([`docs/benchmark/README.md`](../benchmark/README.md); `RESULTS.md` missing — see note at top).
5. **Privacy-By-Design Ephemeral Media Handling:** Zero permanent server storage of audio files, strict DNS SSRF protection (`_assert_public_host`), and PostgreSQL RLS (`0001_user_data.sql`).

### 2.2 Weaknesses (Internal, Negative / Current Limitations) `[VERIFIED FROM MY CODE]`
1. **Four-Quality Backend Chord Vocabulary (`analysisVersion: 2`):** While the frontend Chord Library (`chordTheory.ts`) supports `33` chord qualities (`396` chords), the backend HMM Viterbi detector (`analysis_engine.py`) currently classifies segments into `4` chord qualities per root (`major`, `minor`, `7`, `m7` = 48 templates + `N`). Complex jazz extensions (`maj9`, `dim7`, `aug`, `sus4`) in the audio are mapped to their closest triad or seventh equivalent.
2. **Phase/EQ Browser Stem Separation vs. Neural Source Separation:** Both the active 2-stem phase-cancellation utility (`stemSeparation.ts`) and the prepared 4-lane cascaded BiquadFilter mixer (`stemMixer.ts`) rely on stereo panning ($L-R$ vs. $L+R$) and frequency crossover bands (`200 Hz`, `5 kHz`). On mono recordings or heavily panned mixes, frequency/phase bleed occurs compared to GPU-based deep neural networks (e.g., Demucs).
3. **Prepared Modules Not Yet Wired to Active UI Routes:**
   - The 4-lane `StemMixer.tsx` component (`frontend/src/components/analysis/StemMixer.tsx`) is implemented and unit-tested (`stemMixer.test.ts`), but `Analysis.tsx` currently renders the simpler 2-stem `separateStems` UI.
   - The 7-table relational song-sheet migration (`0002_song_sheet.sql`) is defined in `supabase/migrations/`, whereas `songStore.ts` currently saves song lyrics only to `localStorage`.
   - `Community.tsx` (`frontend/src/lib/community.ts`) and `Plans.tsx` (`frontend/src/lib/plans.ts`) operate as local/informational MVP prototypes without backend persistence or live payment gateway integration.
4. **Monophonic Root-Note Matching in Practice Mode:** Live microphone verification (`Practice.tsx`) uses the monophonic YIN pitch detector (`pitch.ts`) to check whether the user's fundamental pitch matches the active chord's root note, rather than full polyphonic multi-string chord recognition.

### 2.3 Opportunities (External, Positive) `[ASSUMPTION/RECOMMENDATION]`
1. **Integration of Full `v3` Backend Analysis & Prepared Modules:** Mounting `StemMixer.tsx` into `Analysis.tsx`, wiring `songStore.ts` to the `0002_song_sheet.sql` Supabase tables, and expanding `analysis_engine.py` templates to include `sus2/sus4/maj7/dim` (`v3` types already prepared in `frontend/src/lib/api.ts`) can rapidly elevate the MVP to a full commercial release.
2. **B2B Music School & Classroom Adoption:** Music academies and private instructors can use Wilsify AI's custom-branded A4 vector PDF lead sheets (`pdf_export.py`) and shareable song sheets to standardize lesson materials.
3. **WebAssembly / WebGPU Neural Stem Separation:** Future browser support for WebGPU (`ONNX Runtime Web`) would allow running lightweight neural stem separation models directly in the client browser while preserving zero-server-GPU costs.
4. **Regional & Independent Music Markets:** Because Wilsify AI computes chords directly from audio signal harmony rather than relying on pre-existing Western tab catalogs, it works equally well for Indian film/indie music, regional folk songs, and original student compositions.

### 2.4 Challenges (External, Negative / Market & Technical Hurdles) `[ASSUMPTION/RECOMMENDATION]`
1. **Anti-Bot & Terms-of-Service Restrictions on Video Platforms:** Platforms like YouTube frequently update stream throttling, bot-detection CAPTCHAs, and IP blocks that can break `yt-dlp` extraction in `/api/fetch-media`.
2. **Acoustic Ambiguity in Dense Commercial Mixes:** Heavily distorted guitars, loud polyphonic synthesizers, key modulations, or rubato (non-constant tempo) live performances remain challenging for CQT chroma and beat-tracking algorithms (`timeSignatureStatus` is always marked `"estimated"` in `analysis_engine.py`).
3. **Browser Microphone Hardware Variance:** Built-in laptop and mobile microphones apply aggressive OS-level noise suppression and auto-gain control that can clip sustained acoustic guitar decay during YIN pitch detection.
